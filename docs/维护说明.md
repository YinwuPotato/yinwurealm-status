# YinwuRealm 状态监测维护说明

维护：Soidraw。

状态页位于 <https://yinwupotato.github.io/yinwurealm-status/>，监测网址为 <https://www.yinwurealm.org/>。检测运行在 GitHub Actions，官网服务器不运行监测程序。

## 运行方式

Cloudflare 定时调用 GitHub API，启动 Upptime 原生工作流。每小时第 3、8、13……58 分钟检测官网；GitHub 原生 Uptime 定时保留为北京时间每天 12:01 的备用检查。完整时间表和 Worker 操作见 [Cloudflare 调度说明](../cloudflare/README.md)。

官网返回 HTTP 200 且正文包含 `YinwuRealm` 时视为可用；响应超过 10 秒时标为响应较慢。发生故障时自动创建 Issue，恢复后关闭；短暂故障记录也保留。当前不发送邮件或 Discord 通知。

| 数据 | 保存或更新方式 |
| --- | --- |
| 可用状态、故障与恢复 | 每五分钟检测；状态变化时保存记录并更新汇总 |
| 响应时间样本 | 每六小时由 Response Time CI 保存 |
| 汇总与曲线 | 每日由 Summary CI、Graphs CI 更新 |
| 状态页程序 | 每日重新生成；打开页面时另行读取当前数据 |

已打开的状态页不会定时刷新，需要手动刷新或重新打开；读取结果也可能受到缓存影响。普通检测在状态不变时不会新增 Git 提交，最近一次执行时间应看 Actions，不能只看 `history/website.yml` 的 `lastUpdated`。

## GitHub 配置

仓库为 `YinwuPotato/yinwurealm-status`，默认分支 `master`。Issues 已启用，GitHub Pages 从 `gh-pages` 分支根目录发布。

Actions Secret `GH_PAT` 用于保存监测数据、管理故障记录、维护工作流和发布网页。使用仅授权此仓库的 fine-grained PAT；权限为 Actions、Contents、Issues、Workflows 的 Read and write。不要将令牌写入代码或文档。

Cloudflare 使用另一枚仅具备本仓库 Actions 读写权限的令牌，保存为 Worker Secret `GITHUB_DISPATCH_TOKEN`，只负责启动任务。两枚令牌到期时分别续期并更新保存位置。

配置已关闭自动修改仓库简介、Topics 和 Homepage；无需为这些操作添加管理权限。`secrets: []` 表示不向检测程序传入通知凭据，不影响工作流使用 `GH_PAT`。

## 修改与发布

修改前同步机器人产生的提交：

```powershell
git pull --rebase origin master
```

主要编辑 `.upptimerc.yml`。添加监测网址时使用唯一且稳定的 `slug`，不要随意更改已有 slug。修改后提交并推送：

```powershell
git add .upptimerc.yml
git commit -m "更新监测配置"
git push origin master
```

随后确认 Setup CI 成功，继续检查后续 Uptime CI。工作流文件由 Upptime 维护，不应只改 `.github/workflows` 而漏掉配置源文件。

站点图标放在 `assets`。当前图标配置使用状态页自身的完整 HTTPS 地址，避免静态导出器将图像路径当成网页目录。导航与状态页地址需要保留仓库名 `/yinwurealm-status/` 前缀。

## 检查运行情况

1. Cloudflare 日志应出现 `dispatch_accepted`。这表示 GitHub 接受了请求。
2. GitHub 对应运行的触发类型为 `workflow_dispatch`，确认检测步骤完成。
3. 结合 Issues 和状态数据判断官网是否正常。任务显示绿色表示检测流程执行成功，不代表被监测网站必然正常。
4. 每日或每周任务要分别查看对应工作流，不能只凭 Uptime CI 成功就认定其他任务正常。

需要立即复查时，可在对应工作流中使用 Run workflow。避免与自动任务同时手动启动，以免混淆验证结果。

## 数据与备份

长期数据来自 `history/website.yml` 的 Git 历史、`history/summary.json` 和故障 Issues；图表位于 `graphs/website`，徽章数据位于 `api/website`。

删除 Actions 运行记录会丢失执行日志，不会删除已经写入 Git 的监测数据。正常运行后不要压缩或清空监测提交历史，否则会影响历史统计。备份同时保留 Git 历史和当前文件，不能只下载源码 ZIP。

README 状态区域、`api`、`graphs`、`history` 由自动任务维护。长期说明放在 `docs`；现有许可证与 Upptime 制作署名保留。
